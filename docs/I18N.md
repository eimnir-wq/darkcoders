# Internationalization (i18n)

## Summary

The application ships with a **bespoke, dependency-free i18n system** (no `next-intl`,
`i18next`, or `react-intl`). It supports 13 locales, full RTL for Arabic, cookie +
`localStorage` persistence, server-side first-paint direction, and automatic browser
language detection with English fallback.

## Files

| File | Role |
| --- | --- |
| `src/i18n/config.ts` | Locale list, metadata, direction, detection helpers |
| `src/i18n/dictionaries/en.ts` | **Canonical** dictionary (`Dictionary` type is derived from it) |
| `src/i18n/dictionaries/{fr,ar,…}.ts` | Translated locales, typed `PartialDictionary` |
| `src/i18n/dictionaries/index.ts` | Locale registry + `deepMerge` fallback resolver |
| `src/i18n/provider.tsx` | React context, `useI18n()`, persistence effects |
| `src/i18n/server.ts` | `getServerLocale()` — reads the `dc.locale` cookie |
| `src/i18n/types.ts` | `DeepPartial<T>` / `PartialDictionary` |

## Fallback strategy

`getDictionary(locale)` deep-merges the locale's partial dictionary **over the English
dictionary**. Any missing key falls back to English automatically — translations can be
shipped incrementally without breaking the UI. `t()` additionally falls back to the
English dictionary and finally to the raw key path.

## Usage

```tsx
"use client";
import { useI18n } from "@/i18n/provider";

const { locale, dir, dict, t, setLocale } = useI18n();

t("hero.ctaPrimary");                       // → "Start Free Trial"
t("compliance.controls");                   // → "controls mapped"
dict.dashboard.tabs.overview;               // type-safe nested access
t("forms.greeting", { name: "Sara" });      // → placeholder interpolation {name}
```

**Rule:** no UI string is hardcoded in components. All copy lives in the dictionaries.

## Direction & RTL

- `dirOf(locale)` returns `"rtl"` for `ar`, `"ltr"` otherwise.
- The server sets `<html lang dir>` from the cookie (`src/app/layout.tsx`).
- The client provider re-applies `document.documentElement.lang/dir` on change.
- Layout uses **logical CSS properties** throughout (`ms-*`, `me-*`, `start-*`,
  `end-*`, `ps-*`, `pe-*`, `text-start`, `text-end`) so the whole page mirrors without
  per-locale overrides.
- Directional icons use `rtl:rotate-180` (arrow-right, chevrons).
- `[dir="rtl"] body` switches the primary font stack to **Noto Sans Arabic**.
- Numerals and technical strings are wrapped with `dir="ltr"` (counters, stat values)
  so mixed content renders correctly.

Verified: with `dc.locale=ar`, `document.documentElement.dir === "rtl"` and
`lang === "ar"`, and `scrollWidth === innerWidth` (no mirrored-layout overflow).

## Persistence & detection

Order of precedence on first load:

1. `localStorage["dc.locale"]` (set by the provider)
2. `dc.locale` cookie (set by `proxy.ts` from `Accept-Language`, or by the provider)
3. `navigator.languages` detection (`detectLocale`)
4. `defaultLocale` = `en`

On change, the provider writes both `localStorage` and the cookie
(`path=/; max-age=31536000; samesite=lax`).

`src/proxy.ts` runs on all non-static routes; if the cookie is absent it detects the
locale from `Accept-Language` and sets it, so the **first server render already has the
right language and direction**.

## Formatting

- Numbers: `Intl.NumberFormat("en-US")` in `src/lib/utils.ts` (`formatNumber`,
  `formatCompact`) — Western digits are used across locales by design (technical data).
- Relative time: `timeAgo()` in `src/lib/utils.ts` (e.g. `4h`).
- Dates: `formatDate()` uses `toLocaleDateString(locale)`, default `en-GB`.
- No locale-specific plural rules are required by the current copy set.

## Adding a language

1. Copy `en.ts` → `<code>.ts`, translate values, export `PartialDictionary`.
2. Register in `src/i18n/config.ts` (`locales` + `localeMeta`, including `dir`) and in
   `src/i18n/dictionaries/index.ts`.
3. Add the code to `metadata.alternates.languages` in `src/app/layout.tsx` (SEO
   `hreflang`) and to the `SettingsTab` language `<select>` options.
4. No component changes required.

## Adding a key

Add it to `en.ts`. It becomes immediately available in every locale (English fallback)
and type-checked via `Dictionary`.

## Known limitations

- The 12 non-English dictionaries translate the UI copy; some long marketing
  sentences are localized but **not professionally proof-read**. Native review is
  recommended before a public launch in each market.
- AI Copilot **response templates** exist in the English dictionary only; non-English
  copilot answers fall back to English text (the *UI* is localized; the generated
  *content* is English). See `HANDOVER.md`.
- No pluralization/ICU message-format support (not needed by current copy).
