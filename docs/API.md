# API

The project exposes exactly **one** HTTP API route. There is no OpenAPI document in
the project; this contract is written directly from the implementation.

---

## `GET /api/health`

**File:** `src/app/api/health/route.ts`
**Methods:** `GET` (and `HEAD`, aliased to the same handler)
**Auth:** none
**Rendering:** `export const dynamic = "force-dynamic"`
**Caching:** `Cache-Control: no-store, max-age=0`

### Request

No parameters, no body, no headers required.

```
GET /api/health
```

### Response — `200 OK`

```json
{
  "status": "ok",
  "service": "dark-coders-web",
  "version": "1.0.0",
  "timestamp": "2026-09-22T16:13:27.977Z",
  "uptimeSeconds": 8
}
```

| Field | Type | Description |
| --- | --- | --- |
| `status` | `"ok"` | Constant health indicator |
| `service` | `string` | Service identifier |
| `version` | `string` | From `npm_package_version`, fallback `"1.0.0"` |
| `timestamp` | `string` | ISO-8601 UTC timestamp |
| `uptimeSeconds` | `number` | `process.uptime()` rounded |

### Errors

The handler has no failure path — it always returns `200` while the server is up. If
the process is not running, the connection fails (no response).

### Dependencies

- Node `process.uptime()` / `process.env.npm_package_version`
- `next/server` `NextResponse`

### Mock / real status

**Real.** This is a genuine runtime health probe (not mocked) and is what the Docker
`HEALTHCHECK` and `docker-compose.yml` healthcheck call.

### Used by

- `Dockerfile` `HEALTHCHECK`
- `docker-compose.yml` `healthcheck`
- Operations / load balancer probes

---

## Routes that are *not* APIs

- `/robots.txt` and `/sitemap.xml` are generated by `src/app/robots.ts` and
  `src/app/sitemap.ts` — metadata routes, not JSON APIs.
- `/icon.png`, `/apple-icon.png` are static image metadata routes.

## Absent API surface

There are **no** endpoints for authentication, users, threats, incidents, compliance,
search, AI queries or data mutation. All interactive data in the UI is served from
in-process repositories (`src/services/repositories.ts`) over deterministic mock data.
The AI Copilot query engine (`src/features/ai-copilot/engine.ts`) runs **entirely on
the client** — there is no server round-trip.

If a backend is added, the natural seam is `src/services/repositories.ts`: convert its
methods to `async` fetch calls and update consumers (they already await nothing today,
so consumers would need `await`/Suspense).
